**한 일** (앱 '기부금영수증' 탭)
1. **발급**: 가정별 1년 헌금 → 신청자에게 모음 (여럿이면 %로, 원 단위 끝수까지 정확히) → 고른 사람 한 번에 발급·인쇄
   - 위쪽 검산: 가정 이름 헌금 합계 = 영수증 대상 + 신청자 없는 가정. 안 맞으면 경고
   - 발급한 뒤 헌금이 바뀌면 '금액 바뀜' 표시 → 다시 발급하면 예전 것은 자동 폐기, 새 번호
2. **법정 서식** (소득세법 시행규칙 별지 제45호의2) A4 한 장씩, 월별 금액, 합계. 교회 직인은 인쇄 후 날인
3. **발급대장**: 일련번호·구분·이름·번호·주소·금액·발급일, 개인/법인 건수·합계, 폐기(사유 남김), 인쇄, 엑셀 내보내기
4. **신청자**: 개인/법인, 주민번호(또는 사업자번호, 검증숫자 확인), 연락처, 주소. 해마다 그대로 이어짐
5. **예전 발급대장 엑셀 가져오기**: 신청자·발급 기록을 한 번에 넣고, 이름이 같은 가정에 자동 연결 (두 사람이면 지난 금액 비율로)

   - 비밀번호를 잊으면 되살릴 수 없음 → 종이에 적어 교회 금고에 보관

**검증**: 단위 테스트 12개 추가(나눔 끝수, 일련번호, 번호 검사, 대장 읽기, 자동 연결, 금고) → 98개 통과,

## 2026-09-28 (15) · 클라우드 설정 오류 고침 (한 사람이 두 역할)

**문제**: 고객이 SQL 을 실행하자 `ON CONFLICT DO UPDATE command cannot affect row a second time` 오류.
사용자 4명 중 **같은 이메일이 두 줄**에 들어가 있었고(한 사람이 두 역할), 오류 한 줄 때문에 SQL 전체가 취소되어 표가 하나도 안 생김.

**고친 것**
- 한 사람이 여러 역할을 가질 수 있게 함 (예: 기장회계와 출납회계를 함께 맡으면 둘 다 쓸 수 있음)
- 같은 이메일을 여러 줄에 써도, 같은 줄을 두 번 써도 오류가 나지 않음. 대소문자 차이도 같은 사람으로 봄
- 앱도 여러 역할을 합쳐서 권한 판단, 계정 화면에 "기장회계·출납회계" 처럼 표시

**검증**: 이 작업 환경의 Postgres 16 에서 실제로 SQL 을 두 번 실행해 오류 없음 확인,
두 역할 → 둘 다 쓰기 가능 / 재정부장 → 보기만 / 등록 안 된 사람 → 없음. 단위 87개, 브라우저 92/92

**결과**: 고객이 새 SQL 실행 → Success. 실제 서버에서 표 3개 생성 확인, 로그인 안 한 사람은 읽어도 빈 결과, 쓰기는 거절됨 확인
