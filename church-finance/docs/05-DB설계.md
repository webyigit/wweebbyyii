# 05. 데이터베이스 설계 (초안)

작성: 2026-09-28 · 과목 코드는 `04-계정과목표.md` 참고.

## 원칙

1. **원본은 '거래 한 건'뿐** — 헌금 1건, 지출 1건, 은행 거래 1건. 누계·잔액·진도율·집계표는 전부 여기서 계산하고 따로 저장하지 않는다. (엑셀의 "지난주 누계 옮겨 적기"가 사라지는 이유)
2. **이름이 아니라 번호로 연결** — 교인·가정·과목 모두 고유 번호. 동명이인·오타·표기 차이(#N/A)가 생기지 않는다.
3. **지우지 않고 표시만** — 삭제는 `deleted=true`. 누가 언제 무엇을 바꿨는지 `audit_log` 에 남는다 (감사 대응).
4. **민감정보는 따로** — 주민번호는 별도 표에 암호화 저장, 기장회계만 열람, 기기(오프라인 사본)로 내려보내지 않는다.

## 표 (테이블)

### 사람

| 표 | 주요 칸 | 설명 |
|---|---|---|
| `users` | id, email, name, role | role: `bookkeeper`(기장회계) · `cashier`(출납회계) · `finance_head`(재정부장) · `pastor`(담임목사) |
| `households` | id, name, receipt_member_id, note | 가정. **영수증 신청자 1명**을 가리킴 (가족 헌금을 이 사람 이름으로 합산) |
| `members` | id, household_id, name, tag, is_anonymous, active | 교인. `tag` 는 동명이인 구분(예: A). 무명은 `is_anonymous` |
| `donor_aliases` | id, text, household_id, member_id | 헌금 기록에 적히는 표기 → 교인/가정 매칭 (`홍길동,김영희`, 은행 메모 `홍길동십일조` 등). 한 번 연결하면 다음부터 자동 |

### 과목·예산

| 표 | 주요 칸 | 설명 |
|---|---|---|
| `funds` | code, name | G(일반) · S(특별) · M(해외선교) |
| `income_categories` | code, fund, group, name, named, needs_note, active, sort | 수입 과목 |
| `departments` | code, name, head_name, sort | 지출 부서 |
| `expense_items` | code, dept_code, fund, name, active, sort | 지출 항목 |
| `budgets` | year, kind(income/expense), code, amount | 연 예산 (과목·항목별) |
| `budget_transfers` | year, from_code, to_code, amount, reason, date | 항목 간 전용 (다음 해 예산 조정 근거) |

### 거래

| 표 | 주요 칸 | 설명 |
|---|---|---|
| `offerings` | id, date, category_code, household_id, member_id, donor_text, amount, method(cash/online), note, bank_txn_id | **헌금 1건.** date 는 그 주 주일 날짜. 주일헌금처럼 이름 없는 건 household/member 비움 |
| `expenses` | id, date, fund, item_code, amount, description, payee, source(fixed/manual/bank), fixed_rule_id, bank_txn_id, receipt_file | **지출 1건** |
| `fixed_expense_rules` | id, week_of_month, description, amount, item_code, payee, valid_from, valid_to | 고정지출 규칙 (첫째 주 사례비 등). 금액이 바뀌면 새 규칙을 valid_from 으로 추가 |
| `bank_accounts` | code, bank, name, purpose | 계좌 |
| `bank_txns` | id, account_code, at, withdraw, deposit, balance, memo, matched_type, matched_id | 은행 거래내역 (엑셀 올리기). 같은 거래 두 번 안 들어가게 (계좌+시각+금액+잔액) 으로 중복 방지 |
| `match_rules` | id, account_code, memo_pattern, target_type, target_code | 은행 메모 → 헌금과목/지출항목 자동 분류 규칙 (사람이 한 번 분류하면 생성) |
| `loans` / `loan_events` | id, name, principal / date, amount, kind | 차입과 상환 |

### 보고·영수증

| 표 | 주요 칸 | 설명 |
|---|---|---|
| `weekly_confirmations` | week_date, report(offering/cashbook), user_id, at | 재정부장·담임목사 '확인' 기록 |
| `receipt_applications` | id, year, household_id, member_id, name, phone, address, submitted_at, source(online/paper) | 기부금영수증 신청 (해마다) |
| `receipt_secrets` | application_id, rrn_encrypted | 주민번호 — **암호화, 기장회계만, 오프라인 사본 제외** |
| `receipts_issued` | id, year, serial_no, application_id, amount, issued_at, pdf_hash | 발행대장 |

### 공통 칸 (모든 표)

`id`(UUID, 기기에서 만듦) · `created_at` · `updated_at`(서버 시각) · `updated_by` · `deleted` · `rev`

## 계산되는 것 (저장하지 않음)

| 화면/출력 | 계산 |
|---|---|
| 주일헌금현황 | 그 주 `offerings` 를 과목별 합계 + 명세, 예산 대비 누계·진도율 |
| 주간 수입/지출 보고서 (`MM-DD`) | 지난주 잔액 + 이번 주 수입 − 지출 = 잔액 (회계별), 지출 상세 |
| 누계 보고서 (`총`) | 연초부터 과목·부서별 합계, 예산 대비 비율, 특별헌금·해외선교 잔액 |
| 개인별 집계 | `offerings` 를 가정·교인별 합계 |
| 기부금영수증 금액 | 가정의 1년 헌금 합계 (이름 기록 과목만, 무명 제외) → 신청자 이름으로 |
| 검산 | 은행 잔액 vs 장부 잔액, 은행 출금 합계 vs 지출 합계 |

## 동기화 (로컬 ↔ 클라우드)

```
[기기]  IndexedDB 사본 ──(보낼 목록: 바뀐 행)──▶ [클라우드 Postgres]
        IndexedDB 사본 ◀──(받을 목록: updated_at > 마지막 동기화)──
```

- 입력은 **항상 기기에 먼저 저장** → 화면이 즉시 반응, 인터넷이 끊겨도 입력됨
- 연결되면 보낼 목록을 올리고, 서버에서 바뀐 행을 받아옴 (몇 초마다 + 화면 켤 때)
- 같은 행을 두 사람이 동시에 고치면 **나중 저장이 이김**, 앞의 값은 `audit_log` 에 남음. 입력 담당이 헌금(기장)·지출(출납)으로 나뉘어 있어 실제로 겹칠 일은 드묾
- 권한은 서버(행 단위 보안, RLS)에서 막음: 출납회계는 헌금 수정 불가, 열람자는 읽기만 등
